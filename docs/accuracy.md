# 日期范围与准确性报告

检查日期：2026-10-14。

## 结论

当前工程能够计算公历 1900-01-01～2200-12-31，但**不能宣称这一范围所有年份或所有浏览器都准确**。计算引擎是当前浏览器自带的中国农历 `Intl` 实现，不是本项目独立的天文历算。没有对未验证年份做准确性保证。

本次对照香港天文台公开表，在 Node.js v22.23.2、ICU 78.3 上检验 5,628 个日期：5,598 个一致，30 个不一致。已知差异没有悄悄修改为天文台值；页面及 CSV 继续按浏览器历法输出，并公开说明限制，避免把不同来源混成一个历法。

## 范围与边界

| 项目 | 行为 |
| --- | --- |
| 输入范围 | 1900-01-01～2200-12-31（含端点） |
| 出生年龄范围 | 0～120 的整数，0 表示只算出生年 |
| 跨越 2200 | 明确截断到 2200，不跨范围转换 |
| 2101～2200 | 仅验证程序边界与功能；未做权威历法对照，不保证准确；页面和 CSV 标注未验证 |
| 1900 | 已做程序边界检查，未做权威历法对照；香港天文台该系列表从 1901 开始 |
| 非法日期 | 拒绝，如 1900-02-29、2100-02-29、4 月 31 日 |
| 对照单位 | 出生后的每个 19 年检查点，比较当年阳历生日的农历月日及闰月标记 |
| 农历年 | 显示出生农历年和 CSV 农历年，不把春节之前日期错误归入当年农历年 |
| 年龄 | 公历年份差，不是虚岁；春节附近不按农历年排序 |

全年可计算边界已运行，**程序能返回结构合理的结果不是权威验证**。

## 新增 2101～2200 年范围

日期上限已从 2100 年扩展到 2200 年，120 岁上限仍适用。现有香港天文台独立样本仍只覆盖原来的 16 个年度片段，没有新增 2101～2200 年权威样本。新增范围的可计算性与输入边界测试不等于农历准确性验证。原有 7 个哨兵日期亦不能认证此新增范围。

在先前逐年版本中，1988-09-18、120 岁会计算至 2108 年，共 121 行。当前改为只显示 19 年检查点：2007、2026、2045、2064、2083、2102 年，其中 2102 年的权威对照限制在可展开说明及统一提示中展示，年份标签只显示年份和年龄。出生年超过 2100 年时，其出生农历和所有结果同样属于未验证推算。

## 独立对照来源与方法

香港天文台 [公历与农历日期对照表](https://www.hko.gov.hk/en/gts/time/conversion.htm) / [文字版索引](https://www.hko.gov.hk/en/gts/time/conversion1_text.htm)。每年数据的直接来源都记录于 `tests/fixtures/hko-samples.json`，例如 `https://www.hko.gov.hk/en/gts/time/calendar/text/files/T1988e.txt`。

从各年**首个明确的农历月首**起解析至 12 月 31 日；该月首之前的日子因文字表只列“日”而没有显式“月”，不纳入样本。因此这些是年度片段，**不是 16 个完整公历年**。文字表的同号月首连续重复时，第二个月首及后续日期视为闰月；此规则来源于月首序列，而非被测引擎。跨春节的农历年份按月首推断。未使用 `Intl` 生成期望值。

## 已知差异：2057 年

本环境的 2057-09-28 为八月三十，天文台表为九月初一；本环境的九月初一为 2057-09-29。直到 2057-10-27，两者农历日差一天；2057-10-28 的十月初一再次一致。该区间共 30 天。

来源：[2057 年文字表](https://www.hko.gov.hk/en/gts/time/calendar/text/files/T2057e.txt)。界面始终展示此说明，并在计算记录及 CSV 中给 2057、2089、2097 年加“远期朔日需复核”说明。CSV 包含这些行说明与整体计算口径；其他未抽样年份也可能存在尚未发现的差异。

天文台对照表另提示：远期朔日/节气时刻计算可能有几分钟的不确定性，接近午夜时可能导致日期差一天。其列出的朔日包括 2057-09-28、2089-09-04、2097-08-07。后两年的此次抽样一致，也不能据此保证未来预测永远不会变动。该提示说明了预测限制，**并不证明本项目已诊断 ICU 差异的具体成因**。

## 运行环境与浏览器验证

出生日期视为中国民用日期，每天使用 UTC 04:00 对应的北京时间中午。UTC 日期运算计算天数差；不使用本机午夜、夏令时天数或 `new Date('YYYY-MM-DD')` 的本地格式化。已比较温哥华、上海与 UTC 三种系统时区，结果相同。

页面在启动时检查 7 个独立参考日期（包括闰二月、2033 闰十一月、世纪末边界），不支持农历、输出格式无法解析或哨兵不符时停止计算。仅检查 7 个日期不构成全范围认证，也无法发现所有可能的错误。

自动检查覆盖：非法日期、春节、普通/闰月、月大小、2 月 29 日、两个生日候选、差值符号、范围截断、同步/异步一致性、CSV 转义与筛选。浏览器交互验证状态见下文。未来可增加全范围独立对照和不同浏览器版本测试；若更换为固定离线数据引擎，须标明来源、版本及再分发条件。

## 复现

开发环境运行 `npm test`，无需联网。测试数据已随源码交付。

若要重新导入，将上述年度原始文字表下载到临时目录（文件名为 `1901.txt` 等），运行：

```sh
npm run fixtures -- /absolute/path/to/hko-tables
npm test
```

导入脚本只读本地文件，不自动联网。它要求全部 16 年、识别日期与月首并检查样本数，不使用当前引擎填补缺失。原始网页/下载编码可能改变，须人工检查来源及导入差异再提交。

## 本次浏览器交互记录

使用 Codex 内置浏览器核对：示例生日（1988-09-18）按默认 100 岁生成 101 行、出生后 4 次重合、只看重合年份筛选为 5 行（含出生年）、原 2100 年上限版本中，2099 年出生的请求正确截断为两年。390 px 视口下页面主体宽度为 390 px，表格在容器内横向滚动。页面无所观测到的脚本错误。

CSV 内容和编码由自动测试验证；内置浏览器的下载事件观察超时，**未确认该浏览器实际保存了导出文件**。尚未实测 Chrome、Safari、Edge 的下载行为。浏览器工具不允许访问 `file://`，因此本次未通过工具实测双击文件的行为；单文件产物做离线资源与脚本结构检查，并通过 HTTP 预览。请首次在目标浏览器打开后复核导出功能。这是验证范围限制，不代表已经发现标准浏览器的导出错误。

在原 2100 年日期上限版本中，年龄上限调整为 120 岁后，已实测网页可提交 120：1988-09-18 出生的请求显示 113 条记录，并明确截断至 2100 年（112 岁）；自动测试另覆盖可完整计算 120 年的生日及 121 岁拒绝。

2200 年范围版本已在内置浏览器实测：1988-09-18、120 岁得到 1988～2108 年共 121 行，并显示新增范围未验证提示；2199-12-31、120 岁仅计算 2199～2200 年并正确显示截断至 2200 年。

## 当前展示：每隔 19 年核对

界面默认最大年龄 120 岁，只列 19、38、57、76、95、114 岁。不列出生年、不列其他年度，也不展示天数差。检查点仍采用实际农历转换，不能把 19 年当成准确重复周期。月、日及闰月标记全部一致才为“同一天”；有效阳历日期的农历生日不同则为“不是同一天”。该年缺失 2 月 29 日时单列“无法比较”，不能当作已判定不同。

当前运行环境中，示例生日（1988-09-18）的 2007、2026、2045、2064 年是同一天；2083 年不是同一天。2102 年推算为不是同一天，但尚未做权威对照验证。上文保留的逐年行数记录为旧版本的验证历史。

当前 19 年界面已在内置浏览器实测：示例生日（1988-09-18）只列 6 个检查点，“只看同一天”显示 4 行；年龄设为 18 时显示无检查点并禁用导出。CSV 自动测试确认保留两类结论且无天数差列。当前自动测试共 19 项通过。
